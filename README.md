## 01. Извлечение прошивки через BOOTSEL

[Перейти к исследованию →](./01-firmware-extraction/)

Исследование механизма загрузки **RP2040** и получения полного дампа прошивки через режим `BOOTSEL`.

В результате был получен полный образ памяти устройства.

**Основной артефакт:**

`firmware_backup.bin`

---

## 02. Анализ прошивки и извлечение PIN

[Перейти к исследованию →](./02-firmware-analysis/)

Статический анализ полученной прошивки позволил обнаружить PIN-код непосредственно в образе памяти.

PIN хранится в прошивке в открытом виде и располагается по фиксированному адресу:

```text
0x10005500
```

Это позволяет получить секрет без взаимодействия с механизмом ввода PIN на самом устройстве.

## 03. Модификация прошивки и обход проверки PIN

[Перейти к исследованию →](./03-firmware-patching/)

Исследование логики проверки PIN показало, что механизм аутентификации может быть изменён непосредственно в прошивке.

Были реализованы два варианта обхода:

### Вариант A — изменение счётчика ввода

Изменение инструкции:

```asm
MOVS R6, #0
```

на:

```asm
MOVS R6, #3
```

позволяет изменить состояние счётчика введённых цифр.

### Вариант B — эмуляция нажатия кнопки

Изменение значения памяти:

```text
MEMORY[0x20002ED0] = 1
```

позволяет программно имитировать нажатие кнопки разблокировки.

**Результат:** устройство разблокируется без корректного ввода PIN.

## 04. Аппаратный brute-force через GPIO

[Перейти к исследованию →](./04-hardware-bruteforce/)

Для проверки устойчивости механизма аутентификации был реализован аппаратный перебор PIN-кода.

Использовались линии энкодера:

```text
GPIO 27
GPIO 28
```

Второе устройство генерирует необходимые импульсы, имитируя вращение энкодера и нажатие кнопки.

Проверка показала отсутствие эффективного ограничения количества попыток.

Для PIN длиной 4 цифры пространство поиска составляет:

```text
10 000 комбинаций
```

## 05. Эмуляция прошивки в Unicorn

[Перейти к исследованию →](./05-unicorn-emulation/)

Для исключения необходимости физического взаимодействия с устройством была реализована эмуляция участка прошивки с использованием **Unicorn Engine**.

В эмулятор загружается ARM-прошивка, после чего моделируется выполнение логики проверки PIN.

Аппаратные обращения, необходимые для выполнения исследуемого участка кода, заменяются эмулируемыми значениями.

**Результат:** логика проверки PIN может исследоваться и использоваться для перебора непосредственно в программной среде.

## 06. Криптоанализ виртуального хранилища

[Перейти к исследованию →](./06-storage-cryptanalysis/)

Отдельно исследовалась защита виртуального хранилища, извлечённого из дампа устройства.

В ходе анализа был восстановлен алгоритм XOR-шифрования, использующий генератор на основе **LCG (Linear Congruential Generator)**.

Особенность реализации заключается в том, что ключевой поток зависит от **LBA (Logical Block Address)**, а не от PIN-кода пользователя.

Для автоматизации расшифровки был реализован:

```text
cybersafe_cipher.py
```

После расшифровки был восстановлен образ файловой системы **FAT12**, из которого удалось извлечь содержащиеся файлы.

# Methodology

Исследование проводилось по принципу постепенного перехода от наименее инвазивных методов к более сложным:

```text
BOOTSEL
   │
   ▼
Firmware Dump
   │
   ▼
Static Analysis
   │
   ├──────────────► PIN Extraction
   │
   ▼
Firmware Patching
   │
   ▼
Hardware Brute-force
   │
   ▼
Firmware Emulation
   │
   ▼
Storage Cryptanalysis
```

Такой подход позволяет независимо подтвердить результаты несколькими методами.
